# 视频生成额度规格（千问 / 元宝 / 豆包）

> 规格来源：2026-08-08 产品确认
> 适用范围：各厂商视频生成的每日免费额度与消耗计算
> 关联代码：`packages/providers/src/qwen.ts`、`packages/providers/src/yuanbao.ts`、`packages/core/src/types.ts`（当前实现与本规格的差异见 §4）

## 1. 千问（通义万相）

### 1.1 每日免费额度

- 每日免费额度：**10 额度 / 天**
- 刷新时间：北京时间 00:00

### 1.2 消耗的决定因素

消耗额度 = f（模型，时长，清晰度），其他选项不消耗额度：

| 维度 | 可选值 | 是否影响额度 |
|---|---|---|
| 模型 | 万相 2.7 / 万相 2.6 / HappyHorse 1.0 Beta | ✅ 是 |
| 时长 | 5s / 10s / 15s | ✅ 是 |
| 清晰度 | 720p / 1080p | ✅ 是 |
| 生成模式 | 多参考生成（最多 5 个图片或视频）/ 首尾帧 | ❌ 否 |
| 智能配音 | 开 / 关 | ❌ 否 |
| 视频比例 | 如 9:16 / 16:9 | ❌ 否 |

### 1.3 消耗规则（万相 2.7 / 2.6 / HappyHorse 1.0 Beta 通用）

消耗表（已确认）：

| 模型 | 时长 | 720p | 1080p |
|---|---|---|---|
| 万相 2.7 | 5s / 10s / 15s | 1 / 2 / 3 | 2 / 3 / 4 |
| 万相 2.6 | 5s / 10s / 15s | 1 / 2 / 3 | 2 / 3 / 4 |
| HappyHorse 1.0 Beta | 5s / 10s | 1 / 2 | 2 / 3 |

- 万相 2.6 / HappyHorse 1.0 Beta 与万相 2.7 **同消耗规则**（已确认）
- 万相 2.7 15s 消耗 720p=3 / 1080p=4 **已实测确认**
- HappyHorse 1.0 Beta 不支持 15s，因此无 15s 行

规律：

```
消耗额度 = 1（基础，5s · 720p）
        + 时长档：5s=0，10s=1，15s=2
        + 清晰度档：720p=0，1080p=1
```

即：**每增加 5 秒 +1 额度，1080p 比 720p +1 额度**。

校验：

| 组合 | 计算 | 结果 |
|---|---|---|
| 5s · 720p | 1 + 0 + 0 | 1 ✅ |
| 10s · 720p | 1 + 1 + 0 | 2 ✅ |
| 5s · 1080p | 1 + 0 + 1 | 2 ✅ |
| 10s · 1080p | 1 + 1 + 1 | 3 ✅ |

### 1.4 限制条件

- **万相 2.6**：多参考生成不支持 15s（限 5s / 10s）；**首尾帧模式支持 15s**（已确认）
- **HappyHorse 1.0 Beta** 不支持 15s 视频生成（只能选 5s / 10s）
- 多参考生成模式最多上传 5 个图片或视频

## 2. 元宝（混元）

### 2.1 每日免费额度

- 每日免费额度：**5 个 / 天**
- 刷新时间：北京时间 00:00

### 2.2 参数与限制

| 维度 | 规格 |
|---|---|
| 时长 | **固定 5s**，不可选 |
| 参考素材 | **仅图片**，最多 **10 张**；**不支持上传视频** |
| 模型 / 清晰度 | 固定（已确认） |

### 2.3 消耗规则

- 每次生成固定消耗 **1 个**额度（即每日最多 5 个视频）

## 3. 豆包（即梦 Seedance）

### 3.1 每日免费额度

- 每日免费额度：**10 点 / 天**
- 刷新时间：北京时间 00:00

### 3.2 参数与限制

| 维度 | 规格 |
|---|---|
| 模型 | **仅 Seedance 2.0 Mini** |
| 时长 | 5s / 10s / 15s |
| 15s 限制 | **仅豆包 VIP 会员可生成 15s**；普通用户前端**隐藏 15s 选项**，只显示 5s / 10s |

### 3.3 消耗规则

| 时长 | 消耗 |
|---|---|
| 5s | 1 点 |
| 10s | 2 点 |
| 15s | 3 点 |

规律：**基础 1 点，每增加 5 秒 +1 点**（消耗只随时长变化，无清晰度维度）。

## 4. 与现有实现的差异（需同步）

| 厂商 | 项 | 本次规格 | 现状 |
|---|---|---|---|
| 千问 | 每日额度 | 10 额度/天 | `ledger.json` 中 qwenwan `dailyQuota=5`；逆向文档记录“5 次/天” |
| 千问 | 消耗计算 | 模型 × 时长 × 清晰度 | `qwen.ts` 固定 5s / 720P / `quota_use=1` / `typicalCostPerCall=1` |
| 千问 | 模型 | 万相 2.7 / 2.6 / HappyHorse | 仅 `wan27` |
| 元宝 | 每日额度 | 5 个/天 | `ledger.json` yuanbao `dailyQuota=5` ✅ 一致 |
| 元宝 | 时长 | 固定 5s | `yuanbao.ts` limits 写“5-10s 高清视频” |
| 元宝 | 参考素材 | 仅图片，最多 10 张 | `yuanbao.ts` 仅支持单张 imageUrl |
| 豆包 | 每日额度 | 10 点/天 | providers 注册表中 seedance 为 TODO 占位（offline） |
| 豆包 | 模型 | 仅 Seedance 2.0 Mini | 未接入 |

后续应把各厂商消耗表落到 `provider_cost_tables`（admin 可维护），并让各 provider 的 `estimateCost` 按本规格计算。
