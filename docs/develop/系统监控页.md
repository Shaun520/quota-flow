# 系统监控页（Admin Dashboard）实现摘要

> 将 `apps/admin` 的「系统监控」页从静态原型（`dangerouslySetInnerHTML` 注入写死 HTML）改为真实数据驱动，并新增告警阈值可配置能力。

## 一、关键决策

| 决策点 | 结论 |
|---|---|
| Supabase 用量 | 用已有数据真实测量，不接 Management API |
| 活跃告警 | 三类：失败率 / 消耗偏离 / cron 异常 |
| 告警阈值 | 可配置（`monitor_alert_rules` 表 + 后台「阈值设置」弹窗） |
| 数据刷新 | 首屏加载 + 手动「刷新数据」按钮，无自动轮询 |

## 三、数据库迁移（0035）

- 新增表 `monitor_alert_rules`：`alert_type` / `provider_id`(可空=全局) / `threshold` / `enabled`，种子为失败率 30%、消耗偏离 20%、cron 窗口 24h。
- 新增 RPC（均 `SECURITY DEFINER` + `is_admin()` 鉴权，返回小 JSON）：

| 函数 | 用途 |
|---|---|
| `admin_dashboard_kpis()` | 活跃团队 / 注册用户 / 今日调用量 / 平均响应时长 |
| `admin_dashboard_trends(p_days)` | 按日期聚合成功 / 失败调用量 |
| `admin_dashboard_provider_health(p_hours)` | 各厂商近 N 小时成功率 |
| `admin_dashboard_supabase_usage()` | 数据库占用 / MAU / 存储（真实测量） |
| `admin_dashboard_alerts()` | 按阈值实时计算三类告警 |
| `admin_get_alert_rules()` | 读取阈值配置 |
| `admin_upsert_alert_rule(...)` | 保存阈值配置 |

## 四、数据口径（诚实标注）

- **Supabase 用量**：数据库占用 `pg_database_size()`、MAU（近 30 天独立用户）、存储 `storage.objects` 均为真实测量；Edge 函数无数据源显示「不适用」；不写死免费层配额。
- **消耗偏离**：`实际 cost_amount` vs `该 provider unit_cost 均值 × 完成数` 的 mode 级近似（精确 duration/resolution 匹配未做，SQL 注释已写明假设）。
- **cron 告警**：退化为「失败运行 / 从未运行」可观测事实，不解析 cron 表达式算延迟；扩展未启用时自动降级为空。
- **平均响应时长**：成功 job 的 `completed_at - created_at` 均值。

## 五、规范符合性

- 所有查询/聚合在 DB 内完成，前端不拉全量再过滤；无 `select('*')`、无大字段/密钥下发。
- 无高频轮询，刷新为手动单次聚合拉取。
- 阈值写入走 `audit_logs`，已纳入审计筛选白名单。

## 六、上线步骤

1. 在 Supabase SQL Editor 执行 `migrations/0035_admin_dashboard.sql`。
2. 确认 `apps/admin/.env.local` 已配置 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`。
3. `pnpm --filter @quota-flow/admin run dev` 登录后打开 `/dashboard` 验证各卡片渲染真实数据。
