## 三、大版本更新风险提示

### 1. Next.js 15 → 16（#80）🔴 高
- **影响面**：`apps/` 下所有 Next.js 应用（admin / web），涉及路由、数据获取、构建配置。
- **风险点**：
  - 升级指南要求逐步迁移，无法直接跨版本跳过校验。
  - 若项目使用 `next.config` 中的自定义行为、中间件（middleware）、`app dir` 内 API Route 约定等，可能受破坏性变更影响。
  - 锁定的 pnpm `overrides`（针对 postcss / sharp 的版本覆写）需重新核对是否与新版本兼容。
- **验证方式**：见第四节。

### 2. Vite 7 → 8（#75）🔴 高
- **影响面**：依赖 Vite 的构建链路——桌面端渲染进程（Electron renderer）及可能基于 Vite 的构建脚本。
- **风险点**：
  - 构建工具链的大版本常伴随默认行为变化、插件兼容性要求（这也正是 #82 plugin-react 6 构建失败的来源）。
  - Electron 打包若使用 Vite 构建产物，需确认产物路径/格式未变。
- **验证方式**：见第四节。

### 3. dotenv 16 → 17（#74）🟡 中
- CLI / 配置读取类依赖，主要影响环境变量加载行为。
- **风险点**：多行变量、键覆盖、解析规则等可能存在不兼容，需确认所有环境变量仍能正确加载。

### 4. commander 12 → 15（#73）🟡 中
- CLI 命令解析库，主要影响 node CLI 脚本。
- **风险点**：选项解析、help 输出、action handler 行为可能调整，需回归验证现有 CLI 命令。

## 四、后续迁移与验证建议

### 短期验证（建议本迭代内完成）
1. **完整自测**：本地 `pnpm dev` 启动 admin / web / 桌面端，走一遍核心流程（登录、列表、额度操作）。
2. **Next 16**：运行 `pnpm build` 确认生产构建通过；执行一次 `next build && next start` 冒烟测试。
3. **Vite 8**：重新构建桌面端渲染进程并打包一次桌面应用，确认产物可运行。
4. **dotenv / commander**：运行一遍依赖这两个库的 CLI 脚本，核对环境变量与命令解析结果。

### 中长期迁移
5. **TypeScript 6（#77）**：待官方迁移指南稳定后，先本地升级跑 typecheck 修复类型错误，再单独开 PR 升级。
6. **@vitejs/plugin-react 6（#82）**：需先解决与当前 Vite 配置的兼容问题，建议在 Vite 8 上核对官方配置样例后升级。
7. **依赖维护节奏**：大版本更新不要随 Dependabot 自动合并，建议在 `dependabot.yml` 中为框架级依赖（next / vite / electron / typescript）配置 `ignore`，由人工分批次推进。

## 五、如何回滚（如需）

由于均为单依赖 squash 合并，若某大版本在运行时暴露问题：定位对应 PR 的合并 commit，用 `git revert <commit>` 回退该依赖变更，重新构建并提交回滚 PR 即可。
